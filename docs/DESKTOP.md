# 桌面聊天预览

这是基础界面的本地候选，使用 Tkinter 和现有 Genesis Core。默认后端是确定性的 `FakeModel`，用于验证窗口操作与对话流程。也可显式选择已经独立核查的本地 Ollama 服务；切换后端或勾选核查确认不表示服务已经成功响应。

## 启动

在仓库根目录使用含 Tkinter/Tcl/Tk 的 CPython 3.12 或 3.13：

```powershell
py -3.12 -B -I -S tools/run_desktop.py
# 可选：从本地合成 HTTP 演示开始
py -3.12 -B -I -S tools/run_desktop.py --synthetic-http
```

上述两种合成模式无需安装 Genesis、下载模型、修改 PowerShell 执行策略或联网获取依赖。缺少 Tk 时应先使用已有命令行合成演示，桌面入口会明确报告环境缺失；不要将导入成功当作窗口已成功显示。

已有本地服务和模型、且已独立核查云功能禁用及运行位置后，可显式选择真实服务模式：

```powershell
py -3.12 -B -I -S tools/run_desktop.py --real-service --endpoint http://127.0.0.1:11434 --model qwen2.5:7b-instruct-q4_K_M --local-service-verified
```

`--real-service`、`--endpoint`、`--model` 和 `--local-service-verified` 必须一起提供，并且不能同时使用 `--synthetic-http`。示例模型必须已在所选服务中存在；界面不会自动发现服务、下载模型、重试、启用云端回退或修改服务配置。`--local-service-verified` 是调用者对前置核查的明确确认，不是程序执行过核查的证明。

安装当前候选后，等价入口为 `genesis-desktop`。安装包与受控发行的验证必须独立执行；新增入口和显式文件清单本身不代表构建、安装、CI 或发布已经通过。

## 使用范围

窗口显示当前后端、状态、消息历史和输入区。本候选的验收请只输入合成内容，例如“合成测试你好”。`FakeModel` 返回固定规则生成的测试回复，不表现真实模型理解能力。

后端选择包含“离线演示”“本地合成服务”和“本地 Ollama”。本地合成服务在随机回环端口启动自己的 `SyntheticOllamaServer`，通过现有 `OllamaModel` 验证 HTTP 对话链路；它不是已安装的 Ollama，也不加载模型。窗口显示后端的连接范围、工作状态和模型标识，不显示合成服务的临时端口。

选择“本地 Ollama”且当前未在处理请求时，才可编辑本地端点和精确模型名称，并勾选“已核查所选服务为本地运行且关闭云功能”。应用前必须完成这项确认。端点继续遵循既有显式回环 IP HTTP origin 约束，不接受 DNS、代理或远程主机；模型名称必须与服务返回值逐字一致。

创建或恢复本地 Ollama 会话不会连接服务。“就绪”只表示配置和会话可供操作，不表示当前服务可用。恢复历史、同 ID 成功回执重放以及并发提交后的回执恢复，都可能没有调用当前选定模型；不能根据历史条数或成功事件把状态显示成当前服务已连接。真实服务是否完成新请求需要独立的实际调用证据，成功回执本身也不等于服务外连已被全面审计。

复选框只记录用户确认，不会检查或改变 Ollama 云功能设置。使用真实模式前，需按 [Ollama 契约](OLLAMA.md) 在界面之外独立核实服务进程配置、云功能禁用、所选模型运行位置和服务端外连。回环地址和复选框都不是 OS 级出站网络保证。

Enter 插入换行，Ctrl+Enter 发送，也可点击“发送”。应用后端或新建会话只在空闲或会话已停止时进行；已有聊天或输入时，先明确确认切换当前视图。临时模式创建新的内存会话，持久预览模式的会话操作见下节；切换视图不删除已有保存记录。

一次只处理一条输入。处理期间不能重复发送或切换后端；窗口继续处理界面事件。只有 Core 成功提交完整轮次后，回复才进入成功历史。失败提示是独立状态，不作为模型回复或成功轮次归档。

预期失败可以点击“重试原消息”再次提交，保留原输入 ID 与原文；没有自动重试。如果输入区已被修改，重试前会确认仍使用失败时的原消息；编辑后的内容也可点击“发送”作为新的输入，不能复用失败请求的 ID。合法文本的空格、中文和换行保持原貌；空白、NUL 或无法编码为 UTF-8 的文本按既有契约拒绝。

默认桌面会话只在内存中，关闭后丢失；不会因为启动界面或选择模型就打开 SQLite 数据目录。新的本地预览持久化须另外明确选择，并使用独立 `local_preview` 数据分类。两种模式都不创建正式伙伴，历史显示也不等于长期记忆。

以上保存边界适用于 Genesis 界面；所选模型服务的独立日志和缓存仍需按其配置核实。模型回复作为不可信的纯文本显示，不执行其中的命令、脚本、链接或工具请求，也不会因此授予权限。

## 保存与恢复候选

原有“对话”和“记录与恢复”页负责聊天及会话保存，本轮另增加“备份与恢复”页，见下节。记录页的保存方式默认“临时，不保存”；选择“本地预览，保存记录”后，须提供仓库外绝对数据根，并明确确认会以明文保存输入（包括失败请求）、已提交回复与执行状态；该数据不是正式伙伴档案，尚无加密或删除工具，备份需另行手动触发。存储确认与本地模型服务核查是两项独立选择，不能相互代替。当前已应用的数据状态和会话 UUID 在页外显示。

命令行也可显式选择。下面使用示例目录，实际执行前应换成自行选择的新建或已有预览目录；默认仍使用 FakeModel：

```powershell
# 首次创建：目录不存在或为空（可仅有保留的合法空初始化锁文件）
py -3.12 -B -I -S tools/run_desktop.py --create-preview "D:\GenesisPreview\example" --preview-data-acknowledged
# 关闭后再次打开：只浏览会话列表，不创建会话或生成回复
py -3.12 -B -I -S tools/run_desktop.py --open-preview "D:\GenesisPreview\example" --preview-data-acknowledged
# 已有会话可明确恢复；将占位符替换为库中的会话 UUID
py -3.12 -B -I -S tools/run_desktop.py --open-preview "D:\GenesisPreview\example" --preview-data-acknowledged --session "<现有会话 UUID>"
```

`--create-preview` 与 `--open-preview` 互斥，两者都要求 `--preview-data-acknowledged`。`--session` 只允许与 `--open-preview` 一起使用；打开但未给 session 时只浏览。未选择创建或打开时，不能单独传保存确认或 session 参数。真实 Ollama 的四项显式参数仍独立要求完整提供，存储选项不会隐式启用真实服务。

“新建预览库”和“打开预览库”是不同操作。创建只接受不存在或除合法空 `.genesis-initialization.lock` 外严格为空的目录；打开要求已有合法 `genesis-local-preview.sqlite3`，不创建缺失库、替代身份或新初始化锁文件。新版本的合作创建者通过该 sidecar 的操作系统锁仲裁；争用时明确提示初始化忙，不自动重试或归为库损坏。应等待其他创建者结束、确认分类后，显式打开已创建的同类库或选新的空目录创建。锁文件会保留，存在不表示仍被占用，不能通过删除它来解除占用；数据库已出现但初始化失败时也不自动重建。旧 `genesis-synthetic.sqlite3` 不迁移、不重标记，也不能与预览库混放同一目录。完整格式、保存范围和非合作写入/文件系统边界见 [本地预览候选](LOCAL_PREVIEW.md)。

打开已有库但尚未选择会话时，只浏览会话 UUID 列表，不新建会话、不调用模型。选择 UUID 后点击“恢复所选会话”；工作线程从同一事务的一致快照加载成功历史，并单独显示没有成功回执的请求。`running` 表示原执行结果未知，不应显示成当前正在生成或已经取消。

从未完成列表选择原消息后，点击“重试所选原消息”并明确确认风险，继续使用该会话中的原请求 ID 和原文。恢复本身不改变旧尝试状态；只有显式重试才按既有规则隔离旧 `running` 为 `unknown`。同 ID 已有成功回执时仅重放，不再生成。编辑内容后发送属于新请求，不修改旧请求原文。

若本次生成路径失败，但同一权威恢复快照已经包含该输入的成功回执，界面展示已提交结果并清除该请求的重试提示，同时说明这是恢复成功提交、本次尝试未成功；不会为此自动重发。恢复回执不是当前模型调用成功的证明。未完成列表中的 `stale` 表示该尝试的上下文已变化、回复未发布，不表示取消。

当前激活的数据根、分类和会话以已应用配置为准。编辑设置不重定向正在使用的工作线程；新设置应用前不能把输入误发到另一会话。新建会话不删除旧会话，清空界面也不删除账本。模型可能在关闭窗口后返回并提交，需要重新打开记录核对，不能把窗口消失当作取消或没有保存。

存储或会话启动失败可能发生在文件或会话已经创建之后。错误提示不能保证未写入；保留现有数据，明确选择打开后核查，不自动再创建或切换数据根。

## 手动备份、验证与恢复候选

“备份与恢复”页提供三个路径字段：“新备份目录”“已有备份目录”“恢复到新目录”。创建目标旁的“选择父目录”只填写新的子目录路径，不立即创建目录；备份目录及恢复目标都要求原先不存在，已有空目录也不能覆盖。

- “备份当前预览库”使用当前已打开的 `local_preview` 数据根；临时模式不可用，未发送草稿不会进入备份。
- “验证备份”核对已有备份，不写入恢复目录，也不需要写入确认。
- “恢复到新目录”从验证通过的备份创建新预览库；临时模式也可执行，不需要先发送消息。
- “打开上次恢复目录”是恢复成功后的独立动作，只打开会话列表，仍须明确选择会话 UUID；不会自动恢复会话或生成。

创建备份和恢复前需勾选“我确认以下明文保存范围和新目录要求”。下方说明为：“备份及恢复会明文保存输入（含失败和未完成请求）、回复与状态；目标必须是不存在的新目录，不覆盖已有文件。”保存会话、应用模型设置或关闭窗口不会自动备份。

备份页有独立的纵向滚动区域，长路径、明文说明和操作结果随可用宽度换行；窗口较小时可使用该页滚轮或右侧滚动条查看下方内容。Tab 与 Shift+Tab 在控件之间移动时，会将获得焦点的控件滚入视野。滚动区域获得焦点时有可见边框，此时 PageUp/PageDown 翻页、Home/End 到达首尾；这些按键不会接管路径输入框的编辑行为，也不改变其他页面的滚动。

备份以独立只读源连接生成一致 SQLite 快照，再核对快照与清单。验证不恢复，恢复也不自动切换正在使用的数据根或会话；完成后仍须明确打开恢复目录、选择会话 UUID。恢复保留身份、Day 0、成功历史与未完成输入，不自动调用模型、重试或把旧 `running` 改成失败。

备份与恢复库都是明文，包含已接收但失败或未完成的输入，不含模型、配置或未发送草稿。操作失败可能留下目录或文件，应保留检查；若发布恢复库后才发生错误，结果可能已经完成，不能一概显示“未恢复”。不删除旧库、不覆盖目标、不自动修复残留。完整格式与边界见 [LOCAL_BACKUP](LOCAL_BACKUP.md)。

任务在独立工作线程内执行，不能借用聊天线程的 SQLite 连接或在后台直接更新 Tk。执行期间禁用聊天发送和会话/后端切换，保留草稿和原有失败重试资格。完成或错误同时显示在各页共用的状态/错误区，详细结果留在备份页。正常关闭等待聊天与备份两个工作线程返回或报错，不把等待说成取消；界面仍须处理事件，而不是在 Tk 线程同步阻塞等待。fatal 路径可以先销毁界面，再由两个工作线程各自收尾，不能据此断言文件没有写入。无窗口回归与真实窗口布局及交互验收分别记录，不能互相替代。

## 线程与关闭

Tk 组件仅由主线程操作。模型、Core 和会话由单个串行工作线程持有，主线程通过命令和事件传递数据，不能在后台线程直接更新 Tk。

`ChatWorker` 构造期间的 `Thread.start()` 抛出异常或中断时，会无条件标记关闭并投递停止命令，然后原样继续传播构造异常。不能依据 `is_alive()` 或线程启动标记断言原生线程尚未创建。迟到的工作线程会观察关闭状态退出；若已进入资源初始化，则在初始化返回后由工作线程退出自己的上下文。此清理不依赖调用者拿到构造结果或消费后续事件，不跨线程关闭资源，也不阻塞等待线程结束。

窗口或 presenter 构造失败、首次轮询调度失败时，拥有者会向已创建的工作线程发出关闭请求，再继续传播异常；不会等待主循环启动后才补做清理，也不会再次调用失败视图的渲染方法。

主循环运行后，轮询、关闭或应用会话等回调发生不可恢复异常时，界面进入显式 fatal 退出路径：请求工作线程关闭，清除重建会话的意图，在该回调内请求 `root.quit()` 并直接销毁 root，避免依赖外层主循环返回后才销毁窗口；`main` 的 `finally` 再做幂等收尾。这个路径不依赖后续轮询、事件消费或渲染。设计目标包括处理同步确认对话框中的模态重入，但不能据此宣称真实原生模态窗口关闭已验收。确认对话框返回后，重试和新建会话也会检查 fatal 状态并停止继续操作。普通回调错误使 `main` 返回失败状态；被 Tk 捕获的 `KeyboardInterrupt` 交给 `main` 重新抛出，`SystemExit` 保持传播。

这些关闭请求都不在 Tk 线程中同步等待。模型和可选存储仍由工作线程退出自己的上下文完成清理；已有模型调用可能继续运行直到返回。销毁窗口不保证工作线程或进程立即退出，也不表示服务端生成已经取消。

桌面默认不使用 SQLite。显式启用持久预览或测试注入存储时，其创建、使用和关闭必须全部位于同一个工作线程；不能把主线程创建的 SQLite 连接交给生成线程。新分类与 Day 0 格式另见 [本地预览候选](LOCAL_PREVIEW.md)，既有 `ConversationStore`、物理 schema v1 和事务规则不因 GUI 恢复而放宽。

正常关闭窗口会停止接收新输入，并等待正在处理的请求返回后关闭工作线程。等待期间不会宣称请求已取消；不可恢复回调错误则走上面的显式退出路径。当前没有取消协议、严格总时限或流式输出；底层模型永久不返回时，正常关闭也无法承诺在固定时间内完成。不要用后台线程继续运行却显示“已取消”的方式掩盖这个限制。

预期模型错误只显示安全分类。意外错误不能被转换成成功回复，也不能把原始异常、输入正文或 traceback locals 当作界面诊断日志。若意外错误发生在提交之后，界面不能据此断言轮次没有提交；应停止使用该工作线程，并保留结果未知的边界。失败、关闭和成功状态要明确区分。

聊天工作线程运行函数内部遇到内置 `KeyboardInterrupt` 或 `SystemExit` 时，先清理资源并报告中断，再以不携带原始参数、链或 notes 的同类新异常继续传播；原异常对象不被修改，异常对象身份和原始内容不保留。这与上面调用者线程中的构造异常原样传播是不同边界。其他自定义 `BaseException` 子类仍按原异常传播，不能据此宣称所有异常日志都已脱敏。生产代码不修改全局 `threading.excepthook`。

## 验证要求

源码回归使用合成数据和临时资源，不需要真实 Ollama：

完整回归中的 CI 结果解析测试会执行工作流内的 PowerShell 片段，因此除对应 Python 和 Git 外，还需要测试环境已有 `pwsh` 或 Windows PowerShell。测试不会自动安装它们。这只是该回归测试的前提，Genesis 核心运行没有 PowerShell 依赖。

新增桌面回调语义回归需要可导入 `tkinter.CallWrapper`，用于检查 Tk 实际的异常捕获行为；这些回归结合真实 `CallWrapper` 与合成窗口、模态重入，不创建 Tk/Tcl 解释器或原生窗口。完整回归因此需要 Python 的 Tkinter 模块可用，但 Genesis 核心运行库和非 GUI 功能本身仍不依赖 Tk。该测试范围不构成真实原生窗口的显示、交互或关闭验收。

```powershell
py -3.12 -B -I -S tools/check_loopback_tests.py
py -3.13 -B -I -S tools/check_loopback_tests.py
git diff --check
```

工作线程测试应覆盖成功上下文、处理中重复提交拒绝、失败后同 ID 原文重试、意外错误不显示成功且不自动重试、关闭等待，以及可选 SQLite 的线程归属。生命周期回归还需注入线程启动中断、presenter 构造、窗口初始化和回调调度失败，核对已启动线程收到关闭并完成资源清理，以及 fatal 路径不依赖下一次事件消费便退出主循环。并发测试使用事件同步，不靠固定 sleep 猜测顺序。

后端测试还应覆盖真实模式确认必需、端点与模型参数验证、命令行参数互斥和完整性，以及创建会话时不连接服务。默认回归仍使用合成 HTTP 服务，不能将这些测试称为真实 Ollama 测试。

无 `.git` 快照验收须从该快照的显式清单派生测试 ID 和总数，再核对逐项结果与唯一摘要，拒绝缺失、重复和库存漂移；库存解析不能另行导入或执行测试。README 中带提交归属的历史测试数量继续保留，不能作为本候选新增测试后的固定总数。

窗口验证应另行核对：真实窗口可显示中文和多行文本、控件在忙碌期间状态正确、发送与重试不会产生重复历史、错误不冒充回复、关闭不会冻结主线程。单元测试、导入检查和窗口视觉检查是不同证据，不互相替代。

获准的真实服务验收需单独记录模型与服务版本、参数、实际回复、耗时和资源情况。通过同一个 presenter/worker 路径进行的真实服务测试可证明该链路，但不能代替实际 Tk 窗口的交互与视觉验证。
