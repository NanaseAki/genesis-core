# 本地预览持久化候选

这是桌面会话保存与恢复的本地候选约定。默认仍是临时内存会话；只有显式选择创建或打开本地预览数据目录后，才使用持久化。保存真实用户输入时必须标记为 `local_preview`，不能继续使用 `synthetic_development`。本候选不启用正式伙伴身份，也不把聊天账本称为长期记忆或成长。

这里描述数据边界和验收要求，不预先声明本轮测试、真实模型、构建或原生窗口验收通过。旧 M2-A 合成验收记录继续归属于原有版本，不能代替新分类的验证。

## 两种数据分类

| 项目 | 原有合成开发数据 | 新本地预览数据 |
| --- | --- | --- |
| 入口 | `SQLiteStore(root)` | `SQLiteStore(root, data_kind="local_preview", mode="create"或"open")` |
| 用途 | 合成测试与开发演示 | 用户明确选择保存的本地预览会话 |
| 固定文件名 | `genesis-synthetic.sqlite3` | `genesis-local-preview.sqlite3` |
| Day 0 `data_kind` | `synthetic_development` | `local_preview` |
| Day 0 `format_version` | `1` | `2` |
| SQLite `application_id` | `0x47454E31`（GEN1） | `0x474C5031`（GLP1） |
| SQLite `user_version` / DDL | `1` / 原 v1 表结构 | `1` / 保持原 v1 表结构 |

新 Day 0 格式与 SQLite 物理 schema 版本分别管理；Day 0 format 2 不代表数据库 schema 升到 v2。格式验证要求所选分类与文件内标记一致，不能只靠改文件名转换数据。

同一数据根不能混放这两个固定数据库文件；任一分类发现另一分类的固定文件都会拒绝继续。旧构造入口仍保留原有合成行为，新界面持久化只能明确选择 `local_preview`。不会读取旧合成身份来初始化预览，也不会修改正式伙伴数据。

## 创建、打开和迁移边界

本地预览要求显式绝对数据根，不使用隐含默认目录或环境变量来悄悄启用保存。数据根沿用仓库外路径检查；数据库、日志和运行数据不得放进源码或发行清单。检查用于防误配置，不是恶意文件系统竞态沙箱。

桌面“记录与恢复”页提供独立创建/打开按钮；命令行对应互斥的 `--create-preview`、`--open-preview`，均要求 `--preview-data-acknowledged`。`--session` 只用于打开已有库时明确恢复会话，未指定时仅浏览；具体示例见 [桌面说明](DESKTOP.md)。

- `create` 只接受不存在或除下述合法空锁文件外严格为空的目录，首次创建新的预览账本 UUID 和 Day 0。已有数据库、混合分类或其他非空目录明确拒绝，不覆盖旧文件。
- `open` 要求既有预览数据库；目录或文件缺失时不创建、不初始化，也不生成替代身份。打开时校验应用标识、schema、Day 0 分类及账本完整性。
- 不支持、损坏或分类不符的数据明确报错，不自动删除、重建、升级或降级。打开合法数据库时，SQLite 自身可能恢复热回滚日志，因此 `open` 不是文件系统级只读操作。

本轮没有迁移器。两个分类保存在独立目录与文件中，旧合成文件不迁移、不重标记；新的预览数据也不能直接当作正式伙伴库启用。将来如需改变物理 schema、合并数据或转为正式身份，须另行定义版本、可恢复副本、身份/来源规则与迁移验收；当前没有该操作入口。

预览账本 UUID 只用于这份数据的连续性，模型名称不决定身份。打开同一合法库保留已有 UUID 和 Day 0；新建会话不会重新创建该库的身份。这个 UUID 的存在不代表正式人格、长期经历或外部权限已经启用。

## 首次创建的跨进程仲裁

新版本的两个数据分类共用数据根内的 `.genesis-initialization.lock`。这是保留的空 sidecar 文件，不存聊天、身份、PID 或占用记录。首次创建路径使用同进程互斥和操作系统锁，把分类检查、预览空目录检查、排他创建数据库、初始化及验证放在同一个仲裁范围；锁内重新检查，避免两个合作的创建者同时通过各自的文件存在检查后，分别创建不同分类的库。

锁只覆盖首次创建，不持有到模型执行或整个数据库连接生命周期。发生锁争用时明确提示初始化忙，不把它当作库损坏，也不在后台等待或自动重试；调用者在其他创建者结束后核对数据分类，显式打开已创建的同类库，或选新的空目录创建。已有库的 `open` 不创建新 sidecar，也不通过初始化锁等待另一个进程完成创建；若打开时数据库仍未初始化完成，可能校验失败，不能改用重新创建来覆盖它。

锁文件在正常退出和崩溃后都保留，操作系统在持有进程退出时释放锁。文件存在不表示仍被占用，也不是应删除的“陈旧锁”；不要删除、替换锁文件或按 PID 判断能否接管。预览空目录检查只豁免这个固定名称的合法普通空文件；其他文件、非空锁文件、符号链接和非普通文件均不能作为例外。

如果创建在数据库文件出现前中断，只留下合法空 sidecar，之后仍可显式 `create`。数据库文件一旦出现，即使为空或不完整，也不自动修复、删除或重建；需要保留现场并明确检查。操作系统释放锁不保证初始化已提交，也不证明数据完好。合法 SQLite 热日志恢复仍遵循前述打开规则。

这是合作的新版本创建者之间的初始化协议，不是文件系统安全沙箱。旧版本或外部写入者不遵循该锁、恶意删除或替换锁文件、硬链接别名以及目录/符号链接竞态均不在保证内；普通文件检查不等于硬链接隔离。不要把活跃数据根放在云同步目录或网络文件系统，也不能据此宣称真实断电、介质故障或跨机器仲裁已经验证。该 sidecar 是运行数据，不进入源码或发行清单。

本轮备份候选也使用同一锁完成产物创建。新版本的数据库首次创建在锁前及锁内检查备份保留名 `snapshot.sqlite3` / `manifest.json`，发现任一文件名就拒绝把该目录作为新账本根；原有库的 `open` 保持兼容。完整备份固定包含快照、清单和普通空锁文件，不能把它当成可清空后重用的数据目录，详见 [LOCAL_BACKUP](LOCAL_BACKUP.md)。

## 明文保存什么

用户必须在创建或打开前明确选择保存，并看见所选目录和明文保存范围。Genesis 不提供数据库加密或密码保护，操作系统文件权限仍是本地访问边界。

持久化沿用事件、请求、尝试和成功轮次账本，包含：

- 预览身份 UUID、Day 0、会话与事件标识、宿主记录的 UTC 时间。
- 已接收的用户输入原文，包含失败、被中断或尚未完成的请求。
- 已成功提交的模型回复原文、模型标识，以及同一轮的成功回执。
- 尝试状态、有限错误码与起止时间；不把异常正文或 traceback locals 当作诊断内容保存。

用户输入在模型生成前的接收事务中保存。因此“没有成功回复”不等于“输入没有落盘”；清空输入框、切换会话或关闭窗口也不删除这些记录。正在输入但尚未发送的草稿不属于请求账本，界面不会把它自动保存成一条请求。

本候选不新增模型权重、API 密钥、生成参数全量快照、端点凭据、录音或屏幕内容的保存。模型服务可能有自己的日志和缓存，需要按其独立配置核实，不能由 Genesis 的保存范围替它作保证。模型回复仍作为不可信文本显示，不执行其中的工具请求或授予权限。

## 会话恢复与未完成请求

存储、模型和 Core 由同一个工作线程创建、使用和关闭。浏览、打开或恢复会话不自动调用模型；恢复时先展示已提交历史，再分别列出未完成请求，不能把失败内容或错误提示伪装成成功对话。

浏览已有库只列出会话，不隐式新建会话。恢复须明确选择一个会话 UUID；新建会话是单独动作，不能把“打开现有库”解释成“生成一个新身份”。会话目录可由 `session_ids()` 独立读取；选定会话的成功历史和未完成请求由 `recovery_snapshot(session_id)` 在同一个只读事务中一致读取，返回 `RecoverySnapshot(session, unfinished_requests)`，避免两次读取之间出现其他进程提交造成遗漏或重复。

原 `get_session()` 与单独的 `unfinished_requests(session_id)` 仍可使用，但工作线程恢复不用两次独立查询拼接快照。未完成记录是不可变 `UnfinishedRequest(user_input, attempts)`；读取不改变尝试状态。这是读取时刻的一致视图，不会阻止其他进程在读取结束后继续提交。

未完成列表包含没有成功回执的请求，包括其 `failed`、`interrupted`、`running`、`unknown` 或 `stale` 尝试。请求按原用户事件 sequence 排序，每个请求的尝试按旧到新排列；已经有 committed 回执的请求整体排除，不重复显示为待重试。

恢复未完成请求后，用户必须明确选择并确认重试。重试继续使用原输入 ID 和原文；修改后的内容只能作为新的输入提交，不能复用旧请求 ID。没有自动重试或启动时补发。

成功回执已经存在时，同 ID、同原文的调用直接重放既有成功轮次，不重新生成。尚未完成的旧 `running` 尝试只表示执行结果未确认；显式重试按既有事务规则将旧执行隔离为 `unknown`。`stale` 表示上下文过期，显式重试重新读取当前成功历史。模型可能因此再次执行，系统不承诺生成恰好一次。

权威账本优先于单次模型调用结果：如果本次生成路径遇到预期模型错误，但同一个 `RecoverySnapshot` 已包含同输入 ID、同原文的成功回执，工作线程发布该成功回执、清除重试资格，并用 `recovered_commit=True` 标明这是并发提交后的结果恢复，不是本次模型调用成功；不会额外发起生成。`recovered_commit=False` 也不证明模型被调用，因为 Core 可能直接重放既有成功回执。

因此恢复历史、成功回执重放和回执调和都不能证明当前选择的 Ollama 已连接或当前模型已运行。界面的中性就绪状态不根据历史条数作这类判断；实际模型调用与服务验收需要单独证据。

## 失败、关闭与结果未知

UI 只在完整成功轮次提交后显示成功历史。模型失败、断连或超时不代表服务端没有执行；数据库在保存失败状态时也可能再失败，不能把界面错误提示当成失败状态已成功写入的证据。COMMIT 已完成但返回丢失时，恢复与同 ID 重放应使用已提交回执，而不是重复发布。

启动阶段也可能部分完成：存储或会话初始化报错之前，数据库文件、Day 0 或会话可能已经创建。安全的启动错误分类不能证明“未写入任何数据”；界面保留现有文件，让用户明确选择打开后核查，不自动重新创建、覆盖或回退到另一数据根。

正常关闭等待当前请求和工作线程资源清理；不可恢复 GUI 回调错误可先退出并销毁界面，再由工作线程自行收尾。两个路径都不取消已经开始的模型调用，没有严格端到端总时限。模型可能在窗口关闭后返回并提交；需要重新打开库核对实际记录，不能仅凭窗口消失断言请求失败或未保存。

完整生命周期及原生窗口验收边界见 [桌面说明](DESKTOP.md)。原有事务、去重与故障矩阵继续见 [持久化契约](PERSISTENCE.md)；新的数据分类不放宽这些规则。

## 验收与尚未提供的能力

测试必须使用合成文本和新建临时目录，即使测试目标的标记是 `local_preview`；不能把真实聊天复制到测试或发行物中。验收应覆盖：分类/应用标识互斥、跨进程首次创建仲裁与锁持有者退出、sidecar 边界、create/open 的文件行为、旧合成数据保留、Day 0 验证、跨进程恢复、不自动生成、未完成请求显式重试、成功回执去重，以及存储线程归属与故障传播。这里列的是验收要求，不预先声明新增锁回归已通过。

新的 [本地预览备份候选](LOCAL_BACKUP.md) 为该分类提供用户手动触发的 SQLite 一致快照、验证及恢复到新目录。它使用独立只读源连接，不复制活跃主文件；恢复保留身份、Day 0 和未完成请求，不覆盖旧库，也不自动选择会话或重试。备份与恢复结果仍是明文，包含已接收但失败或未完成的输入；未发送草稿和临时聊天不在其中。新增能力与验收结果须独立记录，不能从原有会话恢复测试推出。

当前没有完整环境备份、数据库加密、schema 迁移、跨设备同步、分叉合并、自动保留期限或隐私删除工具。原库和恢复副本分别继续写入后会分叉，不能假定以后可自动合并。关闭前后是否完成了某次请求仍需账本证据；聊天历史与数据库快照都不是记忆检索、长期成长或正式伙伴初始化。
