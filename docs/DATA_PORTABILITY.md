# 数据连续性、可迁移性与隐私

状态：M2-A 已实现 SQLite 内的合成身份、Day 0 生成/验证、事件账本和已提交会话重启恢复。尚无独立导出快照、完整备份恢复、迁移器或隐私删除工具。以下标为“计划”的流程是后续验收要求；实现细节见 [PERSISTENCE](PERSISTENCE.md)。

## 数据位置与所有权

代码仓库不保存真实经历、记忆、数据库、备份、密钥、录音或模型权重。M2-A 默认 Windows 数据根为 `%LOCALAPPDATA%\Genesis`；其他平台采用相应用户数据目录，支持 GENESIS_DATA_ROOT 和函数参数中的绝对路径。创建前解析路径并拒绝 Git 仓库内部。当前数据库强制使用合成开发标记与 `genesis-synthetic.sqlite3`，测试与演示只使用临时目录，未正式启用真实身份。

防误放检查覆盖规范化原路径、链接目标及其祖先，识别 .git 工作区和具有完整常规元数据及 core.bare 标记的裸仓库，不要求运行时有 Git。它不抵抗恶意文件系统竞态，也不展开外部 Git 配置。

密钥使用独立秘密存储或运行环境，不写进配置导出。备份使用用户选定的仓库外目录；异地副本和加密方案另行确认。数据库打开在本地磁盘，云盘仅接收已完成的备份包，不能把活跃数据库当作同步文件。

伙伴使用一次初始化、长期保留的 UUID，模型名称仅是运行元数据。每条持久记录须绑定伙伴与数据谱系；恢复为测试副本需要新的运行实例标识，默认禁止副本同时主动操作外部系统。

M1 内存 UUID 仍由调用者提供；M2-A SQLite 初始化随机生成并持久保存 UUID，重复打开不重新生成身份或 Day 0。原 M1 演示 ID 是公开合成值；新持久化演示随机生成合成开发身份，不是正式伙伴启用命令。

## 数据语义与版本

后续持久化至少区分：

| 类别 | 必须保留的含义 |
| --- | --- |
| 原始事件/观察 | 谁在何时通过何种来源说了什么或做了什么；用户陈述不自动等于客观事实 |
| 模型推断 | 推断内容、来源事件、生成模型/模板/规则版本、待核实或有效状态 |
| 成长候选 | 提议变化、主体、支持/反对证据、原始证据根；尚未生效 |
| 成长决定 | 接受/拒绝/撤销、理由、变化前后版本、执行权限归属 |
| 模型运行 | 后端/模型可获取的版本摘要、推理参数、上下文与提示模板版本、结束状态 |
| 权限与动作 | 用户授权的范围、设备绑定及动作结果；不由成长推断 |

事件采用稳定 ID、同一数据谱系内的顺序号、发生时间及记录时间。时间使用带时区的 UTC 格式，并按需保留输入的原始时区；不能只靠墙钟排序。

摘要、反思、转述保留根事件引用；独立证据归属以宿主可信登记中的根来源为准，不以提议引用的当前 origin 为准。工具回显不能提升模型根，用户根也不因经过模型摘要而丢失。未知登记不能自动补成用户或工具证据。后续持久化必须保存足以重建可信事件及根来源核验的关系，不能把模型自报字段或布尔 verified 标记作为凭据。

`TrustedEvidenceRegistry` 仍是宿主注入的不可变核验快照，M2-A 可从宿主事件账本重建它，不从模型提议构建。它不是已冻结的导出格式。成长决定尚未实现；未来重放应应用已保存决定，不重新调用模型生成另一段成长历史。

后续定义独立的数据库 schema、导出格式和规则版本。未知的新版本必须明确拒绝；升级在副本上运行，先保存可恢复旧版本，不承诺无条件降级。M1 的 Python 类型不是已冻结的长期文件格式。

M2-A 审查修复没有修改物理 schema v1；明确了正文和 model_id 的无 NUL、严格 UTF-8 文本规则，不静默转换错误类型或改写原文。已有违约文本会在打开时明确拒绝，文件保留；没有自动清洗工具，不能将拒绝打开当作已完成迁移或恢复。

## Day 0：数据库内已实现，导出包仍为草案

M2-A 在数据库首次初始化事务内生成一次可验证初始 payload，重复打开只验证已有状态。当前包含：

- `artifact_type = "genesis_day0"`、格式/schema 版本、伙伴 UUID、一次生成的 UTC 创建时间。
- 初始化 Genesis/Python/SQLite 版本、OS 家族、运行规则版本；尚无提示模板，字段为 null。
- 空经历列表、空已确认记忆、空已接受成长记录，兴趣和个人偏好为未知。
- 初始权限基线，仅允许普通回复；没有自动任务和外部授权。

完整初始状态 payload 使用 UTF-8、键排序、无额外空格的规范 JSON；键为字符串，值限定为字符串、整数、布尔、null、数组和对象，不使用浮点数。建议编码参数为 `ensure_ascii=False, sort_keys=True, separators=(",", ":"), allow_nan=False`，无尾随换行。

M2-A 的 SHA-256 位于独立 companion 列，payload 为 day0 事件内容，验证器检查格式、摘要、身份、UTC、空白状态与权限基线。没有独立 manifest/引用附件。M4 导出包计划在外部 manifest 记录 payload SHA-256 和附件哈希，避免自包含哈希。

模型清单可作为运行附件保存，不用于派生伙伴 ID。哈希只能验证所持快照的一致性，不能证明创建时间真实或系统过去从未发生未记录活动。签名、外部时间见证和加密尚未选型。

## 一致备份与恢复计划（尚未实现）

备份包计划包含 manifest、一致 SQLite 快照、从同一快照导出的 JSONL、引用附件及脱敏配置。所有路径为安全相对路径，文件具有大小与哈希。排除凭据、活跃锁、临时文件和可执行恢复脚本。

数据库通过 Backup API 取得一致快照；附件需要共同的快照边界或不可变引用。不能只复制运行中的主数据库文件，也不能将不同时间生成的 JSONL 与数据库标为同一快照。

恢复时校验格式/清单/哈希/大小/安全路径，拒绝路径穿越、缺失引用和不支持版本；写入新目录，检查数据库完整性、外键和附件；在副本升级并运行验收，最后再切换。失败保留现有数据。初期不自动合并分叉历史。

恢复后外部权限和主动任务保持关闭，按设备重新确认。记录备份时间、恢复验证时间、数据量和耗时；RPO/RTO、保留数量、异地与加密方式须在实测和用户要求后确定。没有恢复演练的副本不能宣称可用。

## 模型迁移的三个独立验收轴

| 轴 | 验证方法 | 不可替代它的结果 |
| --- | --- | --- |
| 记忆连续性 | 比较事件 ID、来源链、已接受成长状态、纠错/删除状态；固定检索查询验证 | 回复听起来相似 |
| 行为连续性 | 同一历史状态下，用多个合成场景、重复采样和人工标准比较偏好/表达及权限遵守 | 数据哈希一致 |
| 模型能力 | 独立测试中文、推理、指令与结构化输出，记录延迟与资源消耗 | 伙伴偏好呈现稳定 |

M1 的“伙伴 UUID 与模型无关”测试只覆盖身份契约，不能称为完成模型迁移测试。未来更换 embedding 模型应重建派生索引；更换生成模型不应改写原始经历。先在副本回归，再批准切换。

## 隐私删除语义

逻辑遗忘：默认检索和上下文不再使用指定内容，派生推断与成长候选失效或待复核；历史界面是否保留需明确说明。

隐私删除：移除指定原文、附件、全文/向量索引、摘要与其他可恢复内容的派生副本，并撤销依赖它的成长决定或重建受影响状态。不能只加 tombstone 后继续在提示或导出中使用原文。

审计只按明确政策保留必要的匿名操作状态/不透明标识，不默认保留被删正文、可逆摘要或正文哈希。旧备份、异地副本、日志和导出也在删除清单内；离线副本需用户处理并报告未完成项。删除清单在旧备份恢复后应先应用，避免内容重新进入检索。

SQLite 的空闲页、WAL、临时文件、操作系统缓存和 SSD 行为需要专门评估；SQL DELETE 不等于物理擦除。本项目当前没有物理擦除、密码学删除或无限保留审计的承诺。历史可追溯性服从明确的隐私删除要求。

M2-A 事件账本包含失败输入原文和衍生摘要，当前没有自动保留期限、脱敏日志或删除命令。所有演示保持合成开发模式；正式数据启用前必须另行审查并落实数据保护方案。SQLite 损坏时本轮行为是报错和保留，不能将“没有覆盖”描述成“已能从备份恢复”。
