# 愿景

状态：项目目标与约束；实际实现以 README 和 ROADMAP 的状态为准。

Genesis 是长期成长型原创 AI 伙伴系统，受 Neuro-sama 启发，独立设计身份、经历、表达与视觉资产。她的基础语言、知识与推理能力由预训练模型提供，具体能力需要测量。

初始不预设个人经历、固定兴趣或具体性格。初始偏好是“未知”，不能把默认数值零解释为中性人格。诚实说明能力、遵守用户授权、维护数据来源属于运行规则，不属于编造的个人经历。

## 成长的工程定义

一次成长变化应关联真实经历、证据来源、候选、接受或拒绝的决定、变化前后状态和规则版本。仅修改一份角色提示词不能充分满足这个目标。

运行时可以把已接受的状态编译进上下文；初期不要求修改模型权重。变化是否表现为稳定的兴趣或习惯，需要跨会话、不同场景的长期评估。目前没有已验证的自动人格成长算法。

伙伴自身的表述可以作为“她曾这样说”的观察，但不能仅凭重复表述增加独立偏好证据。用户喜欢某事、用户经常谈论某事、伙伴形成兴趣，是不同结论。摘要、反思或转述必须保留原始证据根，避免循环计数。

预训练模型本身包含倾向；完全空白的人格不是已验证能力。后续实验需要比较基础模型、相同模型加成长历史、更换模型保留成长历史，区分模型倾向与互动变化。

## 五项长期原则

1. 成长连续性：实际发生的事件可追溯，推断可修订，成长可撤销。
2. 模型独立性：伙伴 UUID 和成长资产不绑定模型名；模型变化单独记录。
3. 数据可迁移性：导出可读取，恢复有校验，版本升级有测试。
4. 自主性可控：用户可关闭主动行为；成长和模型输出不能授予权限。
5. 可维护性：模块化单体、少依赖、明确契约和可验证的失败语义。

## 范围与非目标

M1 建立工程基础和合成文本流程；M2-A 建立合成开发身份与 SQLite 事件/会话持久化，尚未正式启用真实伙伴。Ollama、真实记忆与成长闭环分阶段接入。桌面、语音、Live2D、游戏属于交互适配层，不应拥有另一套伙伴身份或成长数据库。

初始不建设微服务、向量数据库、通用多代理框架、自动训练、自我修改代码或无限自主循环。不以持续后台活动次数作为成长指标。

本地模式不得静默转向云端 API。未来若支持云端，必须显式选择、说明数据流向，并通过独立的权限策略。

跨模型迁移需要分别报告记忆连续性、行为连续性和模型能力；数据完整不意味着表达行为已经相同，能力更强也不能掩盖记忆损坏。
