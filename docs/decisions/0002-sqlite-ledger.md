# ADR 0002：可选 SQLite 会话账本

状态：M2-A 已完成独立审查并合并到 main（PR #2）。以下保留当时的设计背景；不替代完整备份恢复设计。

保留 M1 内存 Core，通过关键字参数 store 注入 ConversationStore。协议与不可变会话值放在 Core，SQLiteStore 位于 storage；Core 不导入数据库实现，模型不获得存储能力。MemoryStore 仍是记忆记录协议，不机械地把对话账本当成语义记忆。

使用标准库 SQLite、独立 v1 STRICT schema、外键、唯一约束和短 BEGIN IMMEDIATE 事务。成功历史与成功回执共用 turns 行；模型事件、尝试状态、会话 revision 与它同事务提交。生成期间不持有读/写事务，拒绝把内存锁作为跨进程一致性机制。

持久化在接收输入时固定 ID/内容；失败也不能改文。重试将同输入旧 running 尝试标记 unknown 并隔离其提交资格，不保证旧模型已经停止。不同输入以会话 revision 拒绝过期上下文提交。已提交轮次幂等，模型执行不保证恰好一次；不增加分布式锁、租约续期或后台恢复执行器。

首次排他创建数据库，一事务写入 schema、随机 UUID 和规范 Day 0；现有空/损坏/未知版本明确拒绝，不重建。Day 0 仅为 synthetic_development；格式版本和 schema 版本独立，SHA-256 只验证一致性。跨设备备份、恢复、迁移、签名、隐私删除后续另行实现。

事件来源由宿主固定入口赋值；派生根从已存父事件继承，SQL 约束和触发器验证同会话关系。工具回显不能洗成用户根，用户摘要不丢原根。没有自动成长或来源真实性的密码学证明。

代价：失败输入继续保留、可能重复执行模型、竞争请求需显式重试；整段历史读取及全库打开校验尚未做规模基准。真实数据启用和未来 M2-B 取消/超时 UX 需审查这些语义。
