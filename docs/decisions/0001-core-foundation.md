# ADR 0001：独立核心与 M1 范围

日期：2026-10-25。状态：已接受的 Stage 0 决策在 M1 中落实。

## 背景

Genesis 的主要资产是伙伴身份、真实经历与可追溯成长，需要跨模型与设备连续。早期先验证工程边界，避免被桌面、语音和形象集成牵引。

## 决策

自主开发 Python Core，使用模块化单体。具体模型显式注入；SQLite 为初始持久化选择，Ollama 在 M2 接入。AIRI 作为后续交互候选，协议和维护成本仍需验证，不在 M1 深度修改它。

M1 仅实现同步完整文本、内存会话和 FakeModel。记忆/成长保留小型协议及数据类型；没有数据库、自动学习或备份实现。使用标准库 unittest，运行时无第三方依赖。

伙伴身份与模型标识分离。成功输入按会话与输入 ID 重放；失败不提交半轮对话。默认只允许回复，模型请求不暴露状态写入能力。

## 影响

早期可以离线验证错误传播、去重和证据规则。持久化、流式输出与并发能力仍需后续明确设计和测试；M1 不适合记录真实经历。

真实备份与迁移工具必须遵循独立格式规范。模型重复不能累积为独立偏好证据，成长候选不自动生效，隐私删除优先于永久保留个人原文。
