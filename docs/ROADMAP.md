## M1 验收范围

- 不安装 LLM、不访问 GPU、不联网推理；所有测试和演示只使用合成数据。
- 验证输入输出、隔离会话、历史上下文、不可变快照。
- 验证成功重放、ID 冲突、不同 ID 的相同内容、失败后显式重试。
- 预期故障有因果链，意外错误不吞掉；失败无半轮提交。
- 模型只拿到消息与标识，成长只有候选，默认权限只允许回复。
- 直接源码测试和安装后的包测试均可执行；Windows CI 配置不等于已通过远端 CI。

## M2-A 已实现与 M2-B 前门槛

已实现持久化接口、短事务、稳定开发 UUID、数据库内 Day 0 验证、事件来源和跨进程重放。M1 原 57 项测试继续保留。SQLite 能恢复已提交结果不等于已有一致备份、版本升级或隐私删除。

M2-A 与 M2-B1 均已完成独立审查、远端 Windows CI 并合并；遗留 #3/#4 在 M2-B1 处理并验收。P1 也已合并，P2-A 已完成验收合并；许可专项与原字节干净基线的本地限定验收归属保留，不能沿用为新候选或新目标的 CI 结果，具体证据边界见 [发行准备说明](RELEASE_PREPARATION.md)。本地协议合成通过不替代真实本地推理验收，不启用真实数据；未解决阻塞问题不得以模型接入掩盖。

## M2 后续建议顺序

1. 审查 M2-A 事件/尝试状态和 ID 规范；定义流式输出、超时、取消及错误契约，先用可控测试适配器验证。
2. 保留已实现的仓库外数据目录、身份加载和 SQLite 事务回归；扩展适配器时不得让推理期间持有事务。
3. Day 0 数据库内生成/验证已实现；独立快照包与恢复验收仍属 M4，不提前扩大 M2-B。
4. 显式配置本地 Ollama 端点和模型；禁止静默云端回退。使用受控本地 HTTP 测试服务验证协议，再做人工授权的真实模型测试。
5. 测试流式显示与中断：已显示片段要标记不完整，不能进入“成功回复”或稳定偏好的证据。
6. 运行本机基准：冷/热启动首字延迟、生成速度、显存/内存、CPU 卸载、取消效果和持续负载。模型选择与下载单独授权。

M2 通过标准：重启保留身份与已提交历史；重复请求不重复提交；中断/故障明确；数据库不在推理期间持有长写事务；本地后端失败不出网回退。实际质量和性能阈值在基准后确定。

## 后续阶段的关键门槛

M3：观察与推断分离；检索附来源；修订和遗忘传播；摘要或模型重复不形成新证据根。先人工审阅候选，自动接受规则需另行评估。

M4：从新目录恢复；拒绝缺失、损坏和不支持版本；恢复前保留旧数据；分别验收记忆连续性、行为连续性和模型能力；恢复后外部授权关闭。

M5/M6：主动任务可可靠停止，重启不重复触发；交互适配器不成为第二个成长状态所有者；游戏、语音和外部动作经过权限与资源预算检查。

## 仍需实验的假设

7–9B 级四位量化模型和 4k 上下文可以作为本机测试候选，不是已验证配置。更大上下文、模型、语音与渲染共用 GPU 时的延迟和显存风险必须实测。

尚未证明：外部状态驱动的偏好能够长期稳定呈现、任意更换模型仍保持行为、中文关键词或语义检索足够可靠、AIRI 接入不需要较大维护成本。

## Codex 思考强度

建议 M2 使用 High 处理事务、ID、状态机、取消和错误契约；已定方案的文档及简单适配代码可用 Medium。复杂数据损坏或安全边界专项复核可比较 XHigh 的实际收益。更高强度不代替测试，也不决定本地模型的推理参数。
