# 本地预览备份与恢复候选

本候选为用户明确保存的 `local_preview` 账本增加手动备份、验证和恢复到新目录的入口。默认聊天仍使用临时内存；启动界面、发送消息或关闭窗口不会自动创建备份。原 `synthetic_development` 数据不由此入口转换、迁移或备份，正式伙伴身份仍未启用。

本文说明本轮候选的协议和验收边界。候选实现已完成 Windows Python 3.12/3.13 各 467 项源码及无 `.git` 快照回归、两版离线构建/Canary/重建校验，并单独以合成数据完成 Python 3.13 备份页创建、验证、恢复后显式打开及滚动/键盘实窗验收。原生观察只覆盖本机当前显示缩放及所测窗口尺寸，不证明真实用户数据恢复、其他平台或物理故障处理。远端 CI 以本候选 PR 的精确提交检查记录为准；本地验收不替代远端结果。变更后的文件集合须重新核对，旧收据不自动覆盖后续改动，见 [README](../README.md)。

## 三个独立动作

| 动作 | 输入与结果 | 不会发生的动作 |
| --- | --- | --- |
| 创建备份 | 从明确指定的本地预览库取得一致 SQLite 快照，在新的备份目录生成快照与清单 | 不覆盖已有备份，不修改原库身份或尝试状态 |
| 验证备份 | 核对完整备份格式、文件摘要以及快照内部 schema、Day 0 和账本关系 | 不恢复到数据目录，不调用模型 |
| 恢复到新目录 | 从验证通过的备份生成新的本地预览库 | 不覆盖或删除原库，不自动切换当前会话，不自动生成或重试 |

数据根、备份目录和恢复目标均须明确选择仓库外绝对路径。备份与恢复创建的目录必须原先不存在，父目录须已存在；已有空目录也不是可覆盖目标。备份目录不能等于源数据根或与它互为父子目录，恢复目标同样不能与所选备份目录重叠。操作失败后可能留下已创建目录或文件，必须保留核查，不能把报错解释成“没有写入”。本候选不自动删除残留，也不通过再次创建来修复它。

## 备份格式和一致性

完整备份目录严格只包含三个固定文件：`snapshot.sqlite3`、`manifest.json` 和普通空 `.genesis-initialization.lock`。快照不依赖源 WAL 或回滚日志；锁文件由本次备份目录自行创建，不复制源目录的锁文件。验证要求锁文件为零字节普通文件，拒绝符号链接、junction、非普通文件及额外内容。

清单使用独立的 `format_version=1`，与 SQLite 物理 schema v1、Day 0 format 2 分别管理；一个版本号不代表其他格式自动升级。清单只接受以下固定字段，拒绝重复键、多余键、未知格式或版本，不尝试按旧格式猜测打开。

| 字段 | version 1 含义 |
| --- | --- |
| `artifact_type` | 固定 `genesis_local_preview_backup` |
| `format_version` / `data_kind` | 固定 `1` / `local_preview` |
| `database_file` | 固定 `snapshot.sqlite3` |
| `database_size` / `database_sha256` | 已关闭快照的字节数与 SHA-256 |
| `created_utc` | 宿主记录的备份 UTC 时间，不是可信时间证明 |
| `companion_id` / `day0_sha256` | 快照中的身份 UUID 与 Day 0 摘要 |
| `schema_version` / `day0_format_version` | 固定 `1` / `2` |
| `session_count` / `turn_count` / `unfinished_request_count` | 快照中会话、成功轮次与无成功回执请求的数量 |
| `plaintext` | 固定 `true`，明确产物未加密 |

源数据库通过独立的只读 SQLite 连接访问，启用 `query_only`，并使用 [SQLite Online Backup API](https://www.sqlite.org/backup.html) 取得一致快照。备份任务不会借用聊天线程的连接，也不会通过复制活跃主文件来拼凑快照。源库可继续由其他连接使用；所得备份表示一个一致的已提交数据库状态，不承诺包含点击按钮后才完成的所有操作。

只读连接约束原库账本写入，不等于整个源目录在文件系统层面零写入：WAL 模式下 SQLite 可能需要或维护共享内存等辅助文件，具体条件见 [SQLite 的 WAL 只读数据库说明](https://www.sqlite.org/wal.html#read_only_databases)。若热回滚日志、缺失辅助文件或权限条件使数据库无法以只读方式访问，备份明确失败，不为完成备份而修改源 `journal_mode`、执行 checkpoint 或改用可写源连接。目标快照的 `DELETE` 模式规范化只作用于新产物，不能表述成修改原库的日志模式。

备份不暂停、取消或补发模型请求。快照可能包含已经接收、仍无成功回执的请求和 `running` 尝试；这类记录原样保留。模型后来在原库提交的结果不会自动补进已完成备份。

创建备份在新目录内取得共用的初始化锁，并持有至快照、清单与完整产物验证完成。先完成快照，将目标规范为 SQLite `DELETE` 日志模式，关闭后核对摘要及完整账本，最后发布清单并验证三文件产物。只有目录存在或快照文件存在不代表备份完成；后续用户仍可独立验证。清单 SHA-256 用于检查所持文件的一致性，不是签名、身份认证或可信时间证明；能同时改写文件与清单的人可以伪造一致的摘要。

备份使用与两种数据分类首次创建共用的初始化仲裁。合作的新版本 `SQLiteStore` 在首次创建前及锁内拒绝出现保留名 `snapshot.sqlite3`、`manifest.json` 或 `.genesis-restore-staging.sqlite3` 的目录，避免把备份或恢复暂存目录同时作为新账本根；已有数据库的 `open` 不因此新增限制或锁文件写入。仲裁只约束遵守本协议的创建者，不能阻止外部写入者或恶意文件替换。

空锁文件永久保留，不记录 PID、时间或占用状态；只有进程持有的锁表示当前占用。进程退出会释放锁，文件仍存在，不据其年龄或存在性删除“陈旧锁”。锁释放不证明备份已完成：发布清单前的部分目录、清单写入中断和不完整快照仍需明确验证并保留核查。

清单开始写入后发生错误也可能留下完整或不完整的产物，应按结果未知处理并重新验证；不能仅看清单文件名存在就显示成功，也不能自动覆盖它。

## 明文副本的范围

快照保留该账本中的身份 UUID、Day 0、会话、事件、请求、尝试和成功回执，包括已接收但失败或未完成的用户输入、已提交回复及状态。没有成功回复不等于输入没有进入备份。

备份与恢复结果均为明文，没有密码、数据库加密或自动脱敏。它们不包含尚未发送的输入框草稿、临时内存聊天、Ollama 模型权重、服务配置或完整应用安装；也不是录音、屏幕内容或外部附件的备份。Day 0 已记录的必要环境版本元数据仍随账本保留，但不能据此重建运行环境。用户需要自行保管副本，项目没有自动保留期限或隐私删除工具。

这份数据库副本不是长期记忆、成长或跨设备同步。删除原库中的内容也不能自动清除早先备份；未来若实现隐私删除，旧备份、恢复副本和其他导出都需要单独纳入处理范围。

## 验证与恢复边界

验证需要同时检查清单格式、快照文件及摘要，以及数据库应用标识、精确 schema、完整性、外键、Day 0 和账本关系。不能只看 SHA-256 相等便声称数据库可用。只接受 `local_preview` 的 GLP1 数据；不会把旧合成库换名后视为预览库，也不会转换未知版本。

恢复先验证备份，再把快照复制到原先不存在的新目录中的私有暂存文件；按同一份清单重新核对大小、摘要与账本后，以 `os.link` 原子地发布固定名称 `genesis-local-preview.sqlite3`，拒绝覆盖已经出现的目标。正常成功只清理自己创建的暂存链接，不删除原库或用户文件；该发布依赖本地文件系统提供所需硬链接语义，不支持时明确失败，不退回覆盖式复制。

恢复后的库保留原身份 UUID、Day 0、事件 ID、会话 ID、请求原文与成功回执；不重新初始化身份，不进行 schema 迁移，也不改写失败、`running`、`unknown` 或 `stale` 尝试。若发布之后的暂存清理或返回发生错误，应按结果未知处理：恢复库可能已经完成，不能再声称目标不存在或恢复一定失败。保留残留并核验，不能自动覆盖或重试创建。

恢复目录与三文件备份目录不同。恢复发布期间复用同一初始化仲裁，正常完成后保留普通空 `.genesis-initialization.lock` 和活动数据库，清理本次 `.genesis-restore-staging.sqlite3` 暂存链接。若进程在发布前退出，暂存文件仍受保留名保护；即使系统锁已释放，两种数据分类都不能在该目录中新建数据库，默认 synthetic 入口也不能复用它。锁文件存在不表示仍被占用，不按文件年龄或 PID 删除；失败残留不自动清理。初始化协议的合作写入者边界见 [LOCAL_PREVIEW](LOCAL_PREVIEW.md)。

恢复完成不等于桌面已经打开该库。用户须明确选择打开恢复目录、选择会话 UUID，再决定是否重试未完成请求。恢复和验证都不调用模型；显式重试仍沿用原输入 ID 和原文。`running` 表示结果未确认，不能因为数据来自备份就改成“已失败”或“已取消”。

原库和恢复副本起初保留相同身份及历史，之后分别写入便形成分叉。当前没有分叉合并、自动覆盖或冲突调和工具，不能把两个副本同时继续使用后的结果当作可直接合并的同一份账本。请明确选择后续使用的数据根。

## 桌面任务与关闭

桌面候选提供“备份与恢复”页；具体控件与操作见 [桌面说明](DESKTOP.md)。每次操作由用户明确触发，备份任务在独立工作线程中创建、使用和关闭自己的 SQLite 连接，Tk 控件仍只由主线程更新。任务期间禁止发送聊天和切换会话，但保留未发送草稿及原有失败重试信息；临时模式可以验证或恢复已有备份，不能备份内存聊天。

正常关闭会等待正在执行的备份任务完成或报错，不把等待描述成取消，也没有严格总时限。界面停止显示不证明目标目录未写入或已完整写入；遇到中断或错误需要核对保留的产物。此任务不自动发送聊天消息、启动真实模型或切换当前数据根。

宿主 API 为 `create_backup(source_root, backup_dir, *, timeout_seconds=30)`、`verify_backup(backup_dir, *, timeout_seconds=30)` 和 `restore_backup(backup_dir, target_root, *, timeout_seconds=30)`。超时用于协作式进度检查，不能中断所有操作系统调用，也不是严格端到端总时限；不能把超时报错等同于取消完成或没有写入文件。

接口公开的 `BackupError` 仅保留安全分类，不保留调用方活动异常或底层异常的 cause/context，也不改写原共享异常。这些公开错误的常规 traceback 不携带原异常载荷；诊断不得采集 traceback locals。此约束不表示所有程序错误或中断都会被转换为 `BackupError`，`KeyboardInterrupt` 和 `SystemExit` 继续传播。

## 验收要求与限制

新增验收需使用合成文本、独立临时目录及明确同步，覆盖活跃源的一致快照、备份不改写原库账本、清单和数据库篡改拒绝、已存在目标拒绝、失败残留、身份与 Day 0 连续性，以及未完成请求恢复后不自动执行。WAL 辅助文件行为与原库账本连续性须分别核对，不能只凭只读连接选项宣称全目录零写入。GUI 回归还需核对重复点击、任务状态、关闭等待和异常传播；无窗口回归不能证明真实窗口布局或交互已经验收。

此候选只提供本地预览数据库快照的最小闭环，不包含 JSONL、附件、配置导出、加密、自动备份计划、异地复制、备份轮转、模型迁移或完整环境恢复。它不是恶意文件系统替换的安全沙箱，也不提供任意网络文件系统、云同步、硬件断电或介质损坏保证。更完整的长期数据保护计划见 [DATA_PORTABILITY](DATA_PORTABILITY.md)。
